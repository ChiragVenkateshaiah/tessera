## Overview

An operating model defines how a company actually organizes work — structure, decision rights, processes, and governance — to deliver its strategy. Operating model design engagements typically follow a strategy refresh, a merger, or a recognition that the current structure is creating friction (duplicated capability, unclear accountability, slow decisions) that's now big enough to fix deliberately rather than patch incrementally.

## When to Use It

Use this framework when a client's core issue is organizational — not "what should we do" (strategy) but "how should we be structured to do it well." Common triggers: post-merger integration, a strategy pivot that the current structure doesn't support, or persistent cross-functional friction that keeps surfacing in unrelated engagements.

## Framework

1. **Diagnose against strategy, not against org-chart aesthetics.** Start from what the strategy requires the organization to be good at, then assess whether the current structure supports or hinders that — not from a generic view of "good" organization design.
2. **Define the target operating model across four layers**: structure (reporting lines, spans and layers), decision rights (who decides what, at what level), process (how work actually flows across the structure), and governance (forums, cadences, escalation paths). Skipping straight to structure without the other three layers produces an org chart that looks clean but doesn't function differently.
3. **Design decision rights explicitly** — use the RACI/governance methodology page for the detailed technique. Ambiguous decision rights are the most common root cause of the "slow decisions" complaint that triggers these engagements in the first place.
4. **Sequence implementation.** Structural change (org chart moves) is the most visible and slowest-value lever; process and decision-rights changes often deliver faster, lower-disruption improvement and can be sequenced first.

## Common Pitfalls

- **Structure-first design.** Redesigning the org chart before defining decision rights and process produces a new structure that reproduces the old dysfunction under different reporting lines.
- **Copying a "best practice" model without fit-testing.** An operating model that works well for a comparable-looking company doesn't automatically transfer — the target model needs to be derived from this client's specific strategy and constraints.
- **Underestimating change management.** Operating model changes affect careers, reporting relationships, and status — treat the change management workstream (see change management methodology pages) as core to the engagement, not an afterthought.
